## 3. Software risk (request Q2)

The user-space approach (vendor Debian image + `librknnrt` / `rknn-toolkit-lite2` / `rkllm-runtime`) is reasonable for a capstone. Hidden pitfalls:
1. **NPU driver version lock.**
   - RKLLM runtime releases require a minimum RKNPU kernel-driver version (exact minimum per release: UNVERIFIED; check the rknn-llm release notes).
   - Without kernel source we cannot upgrade the driver. Our RKLLM version, and so the supported models and features (multimodal input, LoRA, KV-cache reuse), are capped by what the vendor image ships.
   - **Ask the vendor before paying for:**
     - the output of `cat /sys/kernel/debug/rknpu/version`;
     - the installed RKLLM and RKNN runtime versions;
     - a run of their own RKLLM demo.
2. **Camera is locked to the vendor's drivers.**
   - With no kernel source or device-tree source, we can only use sensors whose driver and ISP tuning (IQ) file are already in their image. The IMX708 route is closed on this board.
   - IMX662 is listed as supported. **Get in writing** that the shipped image captures IMX662 through the **ISP** (processed YUV, not raw) at 1080p30, with an IQ file tuned for *the exact lens module we buy*.
3. **GPL.**
   - The Linux kernel is GPLv2. A vendor distributing a kernel binary must provide the corresponding kernel source on request; Rockchip's NDA covers proprietary parts, not the GPL kernel.
   - It is a legitimate, polite request ("kernel source + device tree for the image you ship").
   - Rockchip's BSP kernel is also public (rockchip-linux GitHub). The board-specific device tree is what we'd lack.
4. **Python on the device.**
   - Debian 12 ships Python 3.11 (from memory, UNVERIFIED). Check that the vendor's rknn-toolkit-lite2 / rkllm wheels match the image's Python.
   - Do not plan on Python 3.13 on the device; Mac and Kaggle parity rules (3.13) apply only to training.
   - Prefer the C++ RKLLM API for the final runtime.
5. **Audio.**
   - One digital mic means no beamforming. Echo cancellation (plan: WebRTC AEC3 with a mic array) must work with a single mic.
   - The speaker output's power and amplifier are unknown versus the plan's dual MAX98357A.
6. **Over-the-air updates and rootfs:** the vendor image is a black box. Keep our software in `/opt/friday` with its own venv so a reflash is reproducible.

## 4. Camera: IMX662 for our tasks (request Q3)

**Sensor facts:**
- 2 MP (1920×1080), 2.9 µm pixel, 1/2.8", STARVIS 2. These are from my memory of Sony's specs, **UNVERIFIED**; get Sony's or Sinoseen's module datasheet.
- The module is fixed-focus (no autofocus), unless Sinoseen offers a motorised (VCM) version.

**Reading (Gate 1) depends on the lens focal length f**, which Sinoseen has not stated. My calculation:
- character height 1.8 mm at 350 mm;
- px = 1.8·f / (350·0.0029);
- horizontal FoV = 2·atan(5.57/2 / f);
- depth of field: F2.0, blur circle 2 px, focused at 400 mm.

| f (mm) | Char height (px) | Horizontal FoV | In-focus band at native resolution |
|---|---|---|---|
| 2.8 | 5.0 | 89.7° | 251–980 mm |
| 4 | 7.1 | 69.7° | 310–563 mm |
| 6 | 10.6 | 49.8° | 354–459 mm |
| 8 | 14.2 | 38.4° | 373–431 mm |

**Reading:**
- **Gate 1 (≥10 px per char, plan §4.1) needs f ≥ about 5.6 mm**, which means a narrower view (≤ about 52°) and a thin in-focus band (about 35–46 cm) for small print.
- A wide lens (f ≤ 4 mm) fails Gate 1 analytically. That is about our low-res stress renders (~8 px glyph height), where the reader still scored 36/40 with 0 wrong numbers, on synthetic images only.
- Fixed focus means small labels must be held at about 35–45 cm; closer gets blurry. IMX708 had PDAF 10 cm–∞; this is the trade.
- For visual Q&A (objects, colours, people), the frame is downscaled to 384², so blur and resolution matter far less.

**Colour.**
- STARVIS 2 is NIR-sensitive. **Order the module with an IR-cut filter** (day-only), otherwise "what colour is it?" will be wrong under sunlight and incandescent light.
- The vendor's ISP tuning is a real advantage over IMX708, which has no RK3576 IQ file (BOM L119–120).

**Recommendation:** IMX662 with an IR-cut filter and **f ≈ 6 mm** is the best fit for reading. Accept about a 50° view for scene questions.
- If Krishna prefers a wider view for VQA, choose f ≈ 4 mm and accept that Gate 1 is not met analytically. Then re-measure reading on real photos (FRIDAY-Real + label photos) before claiming anything.
- The vendor's actual lens options decide this.
